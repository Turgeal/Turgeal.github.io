Q1-(1) [2分] OpenClaw 系统架构与数据分析技能
────────────────────────────────────────────────────────────────────────────────

【系统架构与工作原理】

OpenClaw 是一个基于大语言模型的智能数据分析代理，其核心架构如下：

  用户（自然语言提问）
       ↓
  LLMs（大语言模型）←→ 工具层（Spark SQL / DataFrame / Python）
       ↓
  OpenClaw Agent（任务规划 → 调用工具 → 验证结果 → 迭代修正）
       ↓
  输出结构化答案或代码

工作流程：
  1. 接收用户的自然语言查询（如"分析糖尿病数据的类别分布"）
  2. 将查询拆解为可执行的数据分析任务
  3. 自动生成 Spark SQL 或 DataFrame 代码
  4. 执行代码并验证输出正确性
  5. 若结果错误，自动重新生成并修正（ReAct 机制）

【3个数据分析相关技能】

  1. SQL 代码生成（Text-to-SQL）
     - 根据自然语言问题，自动生成 Spark SQL 语句
     - 示例：输入"统计每个糖尿病类别人数"，生成 GROUP BY 查询

  2. DataFrame 操作（df 分析）
     - 自动生成 .groupBy()、.agg()、.withColumn() 等 DataFrame API 代码
     - 支持 describe()、crosstab()、correlation 等统计操作

  3. 数据可视化与报告生成
     - 结合 Python / matplotlib 生成图表
     - 自动归纳数据洞察（observations & conclusions）

Q1-(3) [3分] 三项数据洞察（含代码、表格、图表）

【观察 1：BMI 是最强的连续型风险因素】

  代码（Spark DataFrame API）：
  df.groupBy("Diabetes_012").agg(
      F.count("BMI").alias("count"),
      F.round(F.mean("BMI"),2).alias("mean_BMI"),
      F.round(F.stddev("BMI"),2).alias("std_BMI"),
      F.percentile_approx("BMI",0.5).alias("median_BMI")
  ).orderBy("Diabetes_012").show()

  表格：
  ┌───────────────┬───────┬──────────┬─────────┬───────┐
  │ Diabetes_012 │ count │ mean_BMI │ std_BMI │median │
  ├───────────────┼───────┼──────────┼─────────┼───────┤
  │ 0.0         │ 213703│   27.74  │   6.26  │ 27.0  │
  │ 1.0         │   4631│   30.72  │   6.96  │ 30.0  │
  │ 2.0         │  35346│   31.94  │   7.36  │ 31.0  │
  └───────────────┴───────┴──────────┴─────────┴───────┘
  结论：糖尿病组平均 BMI = 31.94，已超过肥胖临界值（30），
        无糖尿病组平均 BMI = 27.74，差值约 4.2 个单位。

  图表：obs1_bmi_distribution.png（直方图 + 均值柱状图）


【观察 2：高血压/高胆固醇构成双高风险，身体活动为保护因素】

  代码（Spark SQL API）：
  SELECT Diabetes_012,
         ROUND(AVG(HighBP),3)       AS HighBP_rate,
         ROUND(AVG(HighChol),3)    AS HighChol_rate,
         ROUND(AVG(PhysActivity),3) AS PhysActivity_rate
  FROM diabetes GROUP BY Diabetes_012 ORDER BY Diabetes_012

  表格：
  ┌───────────────┬────────────┬─────────────┬────────────────┐
  │ Diabetes_012 │ HighBP_rate│ HighChol_r  │ PhysActivity_r │
  ├───────────────┼────────────┼─────────────┼────────────────┤
  │ 0.0         │      0.371  │      0.379  │          0.779  │
  │ 1.0         │      0.629  │      0.621  │          0.678  │
  │ 2.0         │      0.753  │      0.670  │          0.631  │
  └───────────────┴────────────┴─────────────┴────────────────┘
  结论：高血压阳性率从无糖尿病组的 37.1% 翻倍至糖尿病组的 75.3%；
        身体活动率随糖尿病风险升高而下降（77.9% → 63.1%）。

  图表：obs2_risk_factors.png（分组柱状图）


【观察 3：年龄是最强的协同风险因子，Income 为保护因素】

  代码（Spark DataFrame API）：
  df.select(F.corr("Diabetes_012","HighBP"),
            F.corr("Diabetes_012","BMI"),
            F.corr("Diabetes_012","Age"),
            F.corr("Diabetes_012","PhysActivity"),
            F.corr("Diabetes_012","Income")).show()

  关键相关系数：
  ┌──────────────────┬────────┐
  │ 特征对           │  相关系数 │
  ├──────────────────┼────────┤
  │ Diabetes_012~HighBP│ 0.272 │
  │ Diabetes_012~BMI  │ 0.224 │
  │ Diabetes_012~Age   │ 0.185 │
  │ Diabetes_012~Income│-0.172 │  ← 收入越高，糖尿病风险越低
  │ Diabetes_012~Phys  │-0.122 │  ← 运动越多，风险越低
  └──────────────────┴────────┘
  结论：年龄增长、高血压、肥胖是主要风险因素；
        高收入、规律运动是主要保护因素。

Q1-(4) [1分] 失败案例分析
────────────────────────────────────────────────────────────────────────────────

【失败案例描述】

  任务目标：要求 LLM（OpenClaw）解释"糖尿病前期（class 1）仅占 1.83%，
             这一不平衡是否会影响模型？如何处理？"

  期望结果：
    → 应明确指出这是严重的类别不平衡问题；
    → 应说明会导致模型对 class 1 的 recall 极低；
    → 应建议使用 SMOTE 过采样 / 欠采样 / class_weight 代价敏感学习；
    → 应建议使用分层采样（stratified split）划分训练/测试集。

  实际结果（OpenClaw 生成的不完整回答）：
    "数据显示大多数受访者没有糖尿病（84.24%）。糖尿病前期占比 1.83%，
     样本较少，建议进一步调查。"

  问题：
    1. 未指出样本不平衡对机器学习模型召回率的严重影响；
    2. 未给出任何具体的数据处理方法或代码；
    3. 未提及 SMOTE、class_weight 等标准处理手段。

【失败原因分析】

  → LLM 的训练数据中，类别不平衡问题的处理属于高阶数据科学知识，
    模型倾向于输出通用性的描述而非专业性诊断；
  → 用户的问法是"解释数据"，LLM 未能自动识别这实际上是一个
    数据预处理/建模前的关键问题；
  → 缺乏对具体数值（1.83%）的敏感性，未能主动量化其对 recall 的影响。

【OpenClaw 最有价值的方面】

  在大数据量（25 万+ 行）探索性分析场景下，OpenClaw 可自动完成：
    - Schema 推断（无需手动定义数据类型）
    - 基础统计量计算（均值、标准差、分位数一步到位）
    - SQL / DataFrame 代码自动生成，省去大量手工编码时间
  最核心的价值在于：将自然语言直接转化为可执行代码，大幅降低大数据分析的门槛。
